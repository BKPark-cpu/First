# 02. 기능 설계서 — 수주·매출 실적 마감 및 경영실적 보고서

| 항목 | 내용 |
|------|------|
| 문서 버전 | v1.0 (2026-10-01) |
| 기준 소스 | `task/scripts/Invoke-PerformanceReport.ps1` |
| 플랫폼 | Windows PowerShell 5.1 (7.x 호환), CSV 입출력, 정적 HTML 보고서 |

---

## 1. 구성도

```
┌──── 원천 시스템 ─────────────────┐      ┌──── 재무 관리 마스터 ────┐
│ 수주잔고 관리 시스템 → 수주실적.csv │      │ 제품군매핑.csv           │
│                     → 매출실적.csv │      │ 사업계획.csv             │
│ 더존(결산)          → 손익실적.csv │      └────────────┬────────────┘
└───────────────┬──────────────────┘                   │
                ▼  task/input/                          ▼
      ┌───────────────────────────────────────────────────────┐
      │ Invoke-PerformanceReport.ps1                          │
      │  ① 읽기·행 검증 → ② 월별 데이터 선택(마감월=스냅샷)    │
      │  ③ 월 단위 검증 → ④ 마감/재오픈 → ⑤ 집계 → ⑥ 출력      │
      └──────┬───────────────────────┬────────────────────────┘
             │ -Close / -Reopen       │ 항상
             ▼                        ▼
  input/closed/YYYYMM/ (스냅샷)    output/YYYYMM/
  input/마감이력.csv (+.bak)        ├─ 경영실적보고서.html · 요약.md
                                   ├─ 집계_전사·제품군·부서·월별추이.csv
                                   ├─ 검증결과.csv · (재마감 시) 변경내역.csv
                                   └─ 확정/경영실적보고서_YYYYMM_vN.html (마감 시)
```

## 2. 데이터 설계

### 2-1. `수주실적.csv` / `매출실적.csv` — 원장 (행 = 계약·세금계산서 1건)

| 항목 | 수주 열 이름 (후보) | 매출 열 이름 (후보) | 필수 | 용도 |
|------|------|------|:--:|------|
| 일자 | 수주일 · 수주월 · 계약일 | 매출일 · 매출월 · 발행일 | ● | 귀속월 (`yyyy-MM`) |
| PJT코드 | PJT코드 · 프로젝트코드 | 같음 | ● | 수주–매출 연결, 변경 추적 |
| PJT명칭 · 거래처 | PJT명칭 · 거래처 · 원청고객사 | 같음 | | 표시 |
| 제품군 | 제품군 | 같음 | ● | 원천제품군 → 매핑 |
| 구분 | 구분 · 사업구분 | 같음 | ● | `구축` / `유지보수` |
| 부서 · 담당 | 부서 · 영업부서 / 담당 | 같음 | | 부서별 집계 |
| 금액 | 수주금액 · 총수주액 | 매출금액 · 공급가액 | ● | |
| 차감 1 | 용역비 | 외주비 · 용역비 | | 빈칸 = 0 |
| 차감 2 | 판매수수료 | 판매수수료 | | 빈칸 = 0 |
| 참조 | 계약번호 · 비고 | 세금계산서번호 · 비고 | | 같은 값의 별건 구분 |

- **순액 = 금액 − 차감1 − 차감2** (수주 = 순수주, 매출 = 순매출)
- 열 이름은 공백을 무시하고 비교합니다 (`PJT 코드` = `PJT코드`). 후보는 `config.json` 의 `orderColumns` · `salesColumns` 에서 추가합니다.
- 금액: `30,000,000` · `30000000원` · `(1,000)`(음수) · `-`(0) 을 인식합니다.
- 일자: `2026-02-15` · `2026. 2. 15.` · `2026/02/15` · `2026-02` · `2026년 2월` · `20260215` 를 인식합니다. 숫자만 있는 값(엑셀 일련번호)은 날짜로 보지 않습니다.

### 2-2. `손익실적.csv` — 월 1행

| 열 | 필수 | 내용 |
|----|:--:|------|
| 월 | ● | `yyyy-MM` |
| 과제기여 | | 국책과제 기여금 |
| 인건비 · 경비 | ● | 관리 손익 기준 |
| 월말인원 | | 인당 지표용 (빈칸이면 인당 지표 생략) |

### 2-3. `제품군매핑.csv` — 마스터

| 원천제품군 | 보고제품군 | 적용시작월 | 적용종료월 | 정렬순서 | 비고 |
|---|---|---|---|---|---|
| DRM | DRM | | | 1 | |
| 전자문서 | 전자문서 | | 2025-12 | 5 | 명칭 변경 전 |
| 전자문서 | 위변조방지 | 2026-01 | | 5 | 2026-01부터 위변조방지로 보고 |
| 위변조방지 | 위변조방지 | 2026-01 | | 5 | 신규 명칭 |
| CMT | 기타 | | | 7 | 단종 제품 |

- 기준월이 `적용시작월 ≤ 기준월 ≤ 적용종료월`(빈칸은 제한 없음)인 행을 씁니다. 여러 행이 맞으면 적용시작월이 가장 늦은 행을 씁니다.
- `정렬순서` 가 보고서의 제품군 행 순서입니다. `유지보수` 는 항상 마지막(TOTAL 바로 위)에 둡니다.

### 2-4. `사업계획.csv`

| 사업연도 | 구분 | 대상 | 지표 | 연간목표(백만원) |
|---|---|---|---|---|
| 2026 | 전사 | 전사 | 순수주 | 30000 |
| 2026 | 제품군 | DRM | 순매출 | 9500 |
| 2026 | 부서 | MCG | 순수주 | 16000 |

- `구분` = `전사` / `제품군` / `부서`. 전사 지표는 순수주·순매출·과제기여·인건비·경비·영업이익 중에서 고릅니다.
- 금액 단위는 `config.json` 의 `planUnit` 을 따릅니다 (기본 1,000,000 = 백만원).

### 2-5. `마감이력.csv` — 스크립트가 관리

| 열 | 내용 |
|----|------|
| 마감월 · 상태 · 버전 | `2026-02`, `마감` / `재오픈`, 1·2·… |
| 일시 · 실행자 · 사유 | 실행 정보 (재오픈은 사유 필수) |
| 해시 | 마감 당시 해당 월 수주·매출·손익 행의 SHA-256 앞 16자리 |
| 수주건수 · 매출건수 | 마감 당시 행 수 |

월의 현재 상태는 그 월의 **마지막 행**으로 정합니다. 스냅샷은 `input/closed/YYYYMM/` 에 표준 열 이름의 CSV 3개로 저장합니다. 재오픈하면 직전 확정본을 `closed/YYYYMM/vN/` 으로 옮깁니다.

## 3. 처리 로직

### 3-1. 월별 데이터 선택

| 순서 | 조건 | 집계에 쓰는 데이터 |
|:--:|------|------|
| 1 | 월 > 대상월 | 쓰지 않음 (W04) |
| 2 | 월이 마감 상태 | **스냅샷**. 입력에도 그 원장의 해당 월 행이 있는데 스냅샷과 다르면 E07 |
| 3 | 그 밖 (미마감·재오픈 중) | 입력 CSV |

입력에 마감월의 행이 없으면 '제공하지 않음'으로 보고 비교하지 않습니다. 그래서 전체 원장을 다시 내려받아도 되고, 당월분만 넣어도 됩니다. 수주와 매출은 따로 판단합니다.

### 3-2. 마감 · 재오픈 결정표

| 명령 | 순서 | 조건 | 결과 |
|------|:--:|------|------|
| `-Close` | 1 | 대상월이 이미 마감 | 실패 ("이미 마감 — 먼저 재오픈") |
| | 2 | 마감 이력이 있고, 대상월 ≠ 최근 마감월 + 1 | 실패 (E08) |
| | 3 | 검증 오류 ≥ 1 | 실패 |
| | 4 | 그 밖 | 스냅샷 저장 → 이력 `마감, v(기존 마감 횟수+1)` → 확정본 저장 |
| `-Reopen` | 1 | 대상월이 마감 상태가 아님 | 거부 |
| | 2 | 대상월 ≠ 최근 마감월 | 거부 (뒤 월부터 역순으로) |
| | 3 | 사유 없음 | 거부 |
| | 4 | 그 밖 | 스냅샷 → `vN/` 보관, 이력 `재오픈` |

`-Close` 가 실패하면 종료 코드 2를 돌려주고, 보고서는 초안으로 만듭니다.

### 3-3. 제품군 결정

```
if 구분 == 유지보수 (maintenanceAsGroup=true)  → 보고제품군 = '유지보수'
else
    기준월 = (mappingBasis == 'report') ? 대상월 : 행의 귀속월
    보고제품군 = 매핑(원천제품군, 기준월)   # 없으면 E04, 보고서에는 '(미매핑)'
```

- **report (기본)**: 보고월 시점의 체계로 3개년을 모두 다시 분류합니다. 2026-02 보고에서는 2024년의 `전자문서` 실적도 `위변조방지` 행에 들어가므로 전년 비교가 같은 기준이 됩니다.
- **transaction**: 거래 당시의 체계를 그대로 씁니다. 과거 보고서와 숫자를 똑같이 맞춰야 할 때 고릅니다.

### 3-4. 의사 코드

```
rows  = 행검증(수주실적) + 행검증(매출실적)            # E02–E06
pnl   = 행검증(손익실적)
data  = 월별선택(rows, pnl, 마감이력, 스냅샷)         # 3-1, E07, I01
월검증(data)                                          # E04, E09, E10, W01–W04
if -Close: 결정표 3-2 → 스냅샷·이력·변경내역
for off in (2, 1, 0):                                 # 전전년·전년·당년
    당월[off] = 합계(data, 대상월 − 12·off)
    누계[off] = 합계(data, FY시작 − 12·off … 대상월 − 12·off)   # 기간에 데이터 없는 달이 있으면 '-'
    영업이익 = 순매출 + 과제기여 − 인건비 − 경비
제품군표·부서표·월별추이·인당 = 같은 기간 규칙
출력(요약.md, 경영실적보고서.html, 집계 CSV, 검증결과.csv)
```

### 3-5. 설계상 결정 사항

| 결정 | 이유 |
|------|------|
| **제품군 변경은 행 추가가 아니라 매핑 마스터로** | 보고서에 행을 추가하는 방식은 보고서마다 수식을 고쳐야 하고, 과거 실적은 옛 이름 행에 남아 전년 비교가 깨짐. 매핑은 원장을 고치지 않고 기준월만으로 신·구 체계를 모두 재현할 수 있음 |
| 유지보수는 제품군과 관계없이 한 줄 | 기존 월간 실적보고 양식과 같게 하고, 유지보수 비중을 바로 계산하기 위함 |
| 보고는 마감 스냅샷 기준 | 같은 월 보고서가 실행할 때마다 달라지지 않게 하기 위함 |
| 재오픈은 최근 마감월만 | 앞선 월을 바꾸면 이후 월의 누계가 모두 바뀜. 역순 재오픈으로 영향 범위를 드러냄 |
| 금액은 원 단위로 계산, 표시만 반올림 | 백만원으로 먼저 자르면 합계가 틀어짐 |
| 기간에 빈 달이 있으면 '-' | 데이터가 없는 것을 0으로 보이면 전년 대비가 왜곡됨 |
| 달성률 색은 경과율 대비 진도 | 연간목표 대비 누계는 연초에 항상 낮아 보임. 비용 항목은 색을 반대로 |
| 검증 오류 행은 집계에서 제외하고 초안 표시 | 오류가 있어도 대략적인 숫자는 볼 수 있게 하되, 마감은 막음 |

## 4. 인터페이스

### 4-1. 명령

```powershell
.\scripts\Invoke-PerformanceReport.ps1 -InputDir <폴더> [-OutDir <폴더>] [-Month yyyy-MM]
    [-Close | -Reopen -Reason "<사유>"] [-Operator <이름>] [-Now "yyyy-MM-dd HH:mm"]
    [-OrdersCsv <파일>] [-SalesCsv …] [-MappingCsv …] [-PlanCsv …] [-PnlCsv …] [-HistoryCsv …] [-ClosedDir …]
    [-ConfigPath <파일>]
.\scripts\Invoke-PerformanceReport.ps1 -SelfTest
```

| 종료 코드 | 의미 |
|:--:|------|
| 0 | 정상 (초안 생성, 마감 성공, 재오픈 성공) |
| 1 | 실행 오류 (필수 파일·열 없음, 재오픈 거부, 자체 테스트 실패) |
| 2 | `-Close` 실패 (검증 오류, 순서 위반, 이미 마감) |

### 4-2. 출력 파일 (`output/YYYYMM/`)

| 파일 | 내용 |
|------|------|
| `경영실적보고서.html` | 보고서 본문(§1–§10). 브라우저에서 열거나 PDF로 인쇄. 다크 모드·모바일 대응 |
| `요약.md` | 같은 내용의 Markdown (메일 본문·위키 붙여넣기용) + 마감 현황 |
| `집계_전사.csv` | 당월·누계 × 지표 × 3개년 (원 단위) |
| `집계_제품군.csv` | 순수주·순매출 × 당월·누계 × 제품군 × 3개년 (원 단위) |
| `집계_부서.csv` | 부서별 누계 순수주 · 전년 동기 · 연간목표 (원 단위) |
| `집계_월별추이.csv` | 3개 사업연도 × 12개월 월·누적 순수주·순매출 (원 단위) |
| `검증결과.csv` | 전체 오류·경고·정보 (수준 순) |
| `변경내역.csv` | 재마감 시 직전 확정본 대비 추가·삭제 행 |
| `확정/경영실적보고서_YYYYMM_vN.html` · `요약_YYYYMM_vN.md` | 확정본 (마감 상태일 때) |

### 4-3. 주요 함수

| 함수 | 역할 | 부작용 |
|------|------|--------|
| `Import-Table` / `Read-TextAuto` | CSV 읽기 (TextFieldParser, UTF-8/CP949 판별) | 없음 |
| `Read-Ledger` / `Read-Pnl` / `Read-Mapping` / `Read-Plan` | 열 매칭, 행 검증 (E02–E06) | 검증 목록 추가 |
