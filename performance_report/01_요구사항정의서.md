# 01. 요구사항 정의서 — 수주·매출 실적 마감 및 경영실적 보고서

| 항목 | 내용 |
|------|------|
| 시스템 | 경영실적 보고 자동화 > 수주·매출 실적 마감 · 경영실적 보고서 생성 |
| 문서 버전 | v1.0 (2026-10-01) |
| 관련 소스 | `task/scripts/Invoke-PerformanceReport.ps1` |

---

## 1. 배경 및 목적

- 월간 실적보고는 수주잔고 시스템과 더존에서 내려받은 엑셀을 사람이 모아서 만든다. 제품군별로 나누고, 3개년 당월·누계를 비교하고, 목표 대비를 계산하는 데 매월 많은 시간이 든다.
- **마감 개념이 없다.** 보고 후에도 원장이 바뀌어 같은 월의 숫자가 보고서마다 달라진다. 무엇이 왜 바뀌었는지 추적하기 어렵다.
- **제품군 명칭·분류가 바뀌면** 보고서의 행과 수식을 직접 고쳐야 한다. 과거 실적과 같은 기준으로 비교하기도 어렵다. 예: 전자문서 → 위변조방지, 조직 변경.
- **목적**
  1. 월 실적을 검증한 뒤 **마감(확정)**하고, 보고서는 마감 데이터로만 만든다.
  2. 마감 후 변경은 **재오픈 → 재마감(버전 증가)**으로만 허용하고, 무엇이 바뀌었는지 기록한다.
  3. 제품군 체계를 **매핑 마스터**로 관리해서, 명칭이 바뀌어도 코드·보고서를 고치지 않는다.
  4. 경영실적 보고서(당월·누계·3개년·목표 대비·제품군·부서·인당)를 **명령 한 번으로** 만든다.

## 2. 범위

| 포함 | 제외 |
|------|------|
| 수주·매출·손익 CSV 검증 (형식·필수값·매핑·중복·정합성) | 원천 시스템(수주잔고 시스템·더존)의 데이터 수정 |
| 월 마감 · 재오픈 · 재마감 버전 관리 | 손익의 제품군별 배분(원가 배부). PMS 도입 후 검토 |
| 경영실적 보고서 HTML·MD, 집계 CSV 생성 | PPT 자동 작성 (HTML을 PDF로 인쇄하거나 표를 복사해서 사용) |
| 제품군 매핑(명칭 변경·통합·단종)과 재분류 비교 | 예측(Forecast) 모델. v1.0은 경과월 단순 환산만 |
| 사업계획 대비 달성률 (전사·제품군·부서) | 메일 자동 발송 (보고서 파일을 사람이 배포) |

## 3. 이해관계자

| 역할 | 관여 내용 |
|------|-----------|
| 재무담당자 | 원천 CSV 내려받기 → 검증 → 오류 수정 요청 → 마감 실행 → 보고서 배포 |
| 영업관리·사업부 | 검증 오류·경고 건(제품군 누락, PJT코드 오입력 등)의 원장 정정 |
| 경영진 | 확정 보고서 열람 |
| 시스템 관리자 | 설정(config.json)·매핑 마스터 관리, 재오픈 승인, 장애 대응 |

## 4. 용어

| 용어 | 정의 |
|------|------|
| 순수주 | 수주금액 − 용역비 − 판매수수료 |
| 순매출 | 매출금액 − 외주비 |
| 영업이익 | 순매출 + 과제기여 − 인건비 − 경비 (관리 손익 기준) |
| 사업연도(FY) | 10월 1일 ~ 다음 해 9월 30일. 끝나는 해로 부른다 (2025-10 ~ 2026-09 = FY2026) |
| 당월 / 누계 | 대상월 1개월 / 사업연도 시작월부터 대상월까지 |
| 3개년 비교 | 당년, 전년 같은 달(같은 기간), 전전년 같은 달(같은 기간) |
| 마감 | 대상월 데이터를 스냅샷으로 고정하고 이력(버전·해시·실행자)을 남기는 것 |
| 재오픈 | 가장 최근 마감월을 사유와 함께 다시 여는 것. 다시 마감하면 버전이 1 오른다 |
| 원천제품군 / 보고제품군 | 원장에 적힌 제품군 / 보고서에 표시할 제품군. `제품군매핑.csv` 로 연결 |
| 유지보수 | 구분이 `유지보수` 인 행. 원천제품군과 관계없이 보고서에서는 `유지보수` 한 줄로 모은다 |

## 5. 기능 요구사항

| ID | 요구사항 | 우선순위 | 비고 |
|----|----------|:---:|------|
| FR-01 | 수주·매출·손익·제품군매핑·사업계획 CSV를 읽는다. 열 순서는 상관없고, 열 이름 후보는 설정으로 바꿀 수 있다 | 필수 | UTF-8·CP949 자동 판별 |
| FR-02 | 필수값(일자·PJT코드·제품군·구분·금액)이 비었거나 형식이 틀린 행은 **오류**로 표시하고 집계에서 뺀다 | 필수 | E02·E03 |
| FR-03 | 원천제품군이 매핑에 없으면 **오류**로 표시한다 | 필수 | E04 |
| FR-04 | 구분 값은 `구축`·`유지보수` (동의어 설정 가능) 외에는 **오류**로 처리한다 | 필수 | E05 |
| FR-05 | 같은 파일 안에서 모든 값이 같은 행은 중복 **오류**로 처리한다 | 필수 | E06. 이중 집계 방지 |
| FR-06 | 대상월의 순수주·순매출 음수, 비용 > 금액, 수주에 없는 매출 PJT는 **경고**로 알린다 | 필수 | W01–W03. 마감은 가능 |
| FR-07 | 대상월 이후 데이터는 보고에서 빼고 건수를 경고로 알린다 | 필수 | W04 |
| FR-08 | 검증 오류가 0건일 때만 마감할 수 있다 | 필수 | |
| FR-09 | 마감은 월 순서대로만 한다. 최근 마감월의 다음 달만 마감할 수 있다 | 필수 | E08 |
| FR-10 | 마감 시 대상월 수주·매출·손익을 스냅샷으로 저장하고, 마감이력에 버전·일시·실행자·사유·해시·건수를 기록한다 | 필수 | |
| FR-11 | 마감된 월은 이후 실행에서 **스냅샷으로 집계**한다. 입력이 바뀌었으면 **오류**로 알리고, 보고 숫자는 바꾸지 않는다 | 필수 | E07 |
| FR-12 | 재오픈은 가장 최근 마감월만, 사유를 입력해야 할 수 있다. 직전 확정본은 보관한다 | 필수 | |
| FR-13 | 재마감하면 버전이 오르고, 직전 확정본 대비 추가·삭제 행을 `변경내역.csv` 로 남긴다 | 필수 | |

## 6. 비기능 요구사항

| ID | 항목 | 요구사항 |
|----|------|----------|
| NFR-01 | 구동 환경 | Windows 기본 PowerShell 5.1에서 별도 설치 없이 동작 (PowerShell 7 호환) |
| NFR-02 | 처리 시간 | 수주·매출 합계 7천 행 기준 15초 안팎 (실측 12초) |
| NFR-03 | 정확성 | 집계 CSV는 원 단위로 저장하고, 보고서 표시만 백만원으로 반올림(사사오입) |
| NFR-04 | 추적성 | 모든 마감·재오픈은 이력에 남고, 확정본은 버전별 파일로 보관 |
| NFR-05 | 무결성 | 마감 스냅샷의 해시로 마감 후 변경을 감지 |
| NFR-06 | 보안 | 데이터를 외부로 전송하지 않는다 (로컬 파일만 사용). 운영 CSV는 저장소에 올리지 않는다(.gitignore) |
| NFR-07 | 유지보수성 | 열 이름·제품군·주기·단위를 `config.json` 과 마스터 CSV로 바꿀 수 있다 |

## 7. 제약·가정

- 수주실적·매출실적은 **행 단위(PJT·계약·세금계산서 단위) 원장**으로 내려받는다고 가정한다. 이미 합계를 낸 표는 넣지 않는다.
- 손익(과제기여·인건비·경비·월말인원)은 더존 등 회계 결산값을 **월 1행**으로 입력한다. 제품군별 배분은 하지 않는다.
- 3개년 비교를 하려면 처음 도입할 때 전전년 사업연도 시작월부터의 데이터가 입력에 있어야 한다. 그 이후에는 마감 스냅샷이 쌓이므로 당월분만 넣어도 된다.
- 사업계획의 금액 단위는 `config.json` 의 `planUnit` 을 따른다 (기본 백만원).
- 수주 원장의 PJT코드와 매출 원장의 PJT코드는 같은 체계를 쓴다.
